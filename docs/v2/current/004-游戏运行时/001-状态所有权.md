# 游戏运行时

> 分类：现状；最后核对：2026-07-21
> 依据：`game-session`、`world-application`、`game-ui`、`game-scene-view`、`game-native-plan`、`game-native-target` 和 `game-host`。

## 状态所有权

| 状态 | 所有者 | 变更入口 | 外层读取形式 |
| --- | --- | --- | --- |
| 产品长期状态、可选真实战斗、冻结规则包和内容包 manifest | `ProductSession` | `ProductSession::transition`、`from_package_save` | `ProductSnapshot`、`ProductEvents` |
| 旧 demo 世界、场景、当前战斗和 roster seed | `GameSession` | `transition`、`advance_world_tick` | `GameSnapshot`、`GameEvents` |
| 产品地图、位置、队伍、经济、flag、训练师状态和活动战斗上下文 | `GameState`（由 `ProductSession` 持有） | foundation 命令与受验证的 `BattleResolution` | `ProductSnapshot::state` |
| 世界地图规则、角色位置和朝向 | `World` | `transition`、`transition_actor` | `WorldOutcome` |
| NPC 脚本进度、角色外观和对白 | `WorldApplication` | 世界命令、`advance_npcs` | `WorldObservation` |
| 对战规则与准入 | `Battle` 及 `BattleRuleset`，由 `BattleApplication`/`ProductSession` 使用 | 对战 action、规则包校验 | 战斗观察、版本化合同、转换结果和回放步骤 |
| 菜单、焦点、动画、控制台和图鉴选择 | `PresentationState` | 归一化输入与 UI action | `PresentationSnapshot` |

`ProductSession` 在 `GameState`、冻结的 `legacy-gen3@1` 规则包、`starter-region@1` 内容包 manifest 与可选 `BattleSession` 之间协调：世界交互先在 `GameState` 建立活动战斗事实，再由显式请求创建真实战斗；只有终局回写成功才清除该事实。规则引用随开战请求、结果补丁和产品存档传播；内容包引用随产品存档传播；恢复时两者都必须匹配。`game-host` 从 `assets/content/starter-region/content.json` 加载静态地图、NPC、训练师、物品、商店、战斗和遭遇，并由 `ContentPackageDocument` 在纯核心中校验后构造内容。`ThinSliceContent::standard()` 只保留为测试/兼容构造器。`GameSession` 保留为旧 demo/展示兼容 API，不是 `game-host` 当前产品页的运行中业务所有者。表现状态是独立的瞬态状态，不能直接修改 `ProductSession`、`GameState`、`World` 或对战状态。

## 启动

```text
game-host
  -> game-fs-assets 读取资产和地图来源
  -> content.json、ContentPackageDocument、CurrentDataSet、ProductSession
  -> 启动期 demo sprite manifest（不保留为运行状态）
  -> NativeAssets
  -> Winit 创建窗口
  -> NativeTarget 创建 WGPU runtime 与文本渲染器
```

`game-host` 持有窗口、native target、表现状态、资产与产品会话。它负责加载失败的展示、存档文件 I/O 和进程退出；这些行为不进入 application 或 domain。

## 输入与逻辑 tick

```text
Winit 事件
  -> punctum-wgpu 输入归一化
  -> FoundationPageAction / Ramus 路由
  -> ProductCommand
  -> ProductSession::transition
  -> ProductEvents + ProductSnapshot
```

`PresentationState` 仍服务旧展示场景。当前产品基础页将移动、交互、遭遇、购买、战斗动作、回放推进和离开终局战斗转换为 `ProductCommand`；runtime 不再以摘要结算命令拼接长期状态。

真实时间由 runtime 持有。旧 demo 世界场景活动时才调用 `GameSession::advance_world_tick`；当前产品基础页不以 runtime tick 改写 `GameState`。

## 场景投影与帧提交

```text
GameSnapshot + PresentationSnapshot + MapProject + AtomicTileCatalog
  -> game-scene-view::project_scene
  -> SceneFrame
  -> game-native-plan::FramePlan
  -> game-native-target::NativeTarget::present
  -> punctum-wgpu::GpuRuntime
```

世界地图使用 Grid view。图鉴、战斗菜单和命令控制台使用 Pixel UI。`SceneFrame` 可以组合 Grid 基础画面与 UI overlay，也可以只包含 UI。所有路径最终产生 `FramePlan`。

场景投影和帧计划可以在没有窗口、GPU 或真实资产路径的测试中构造。GPU 或表面错误只影响当前运行时，不能反向改变游戏规则状态。

## 运行时失败

`game-host` 将启动、资源、场景投影、帧计划和提交失败输出到 runtime 边界。领域和用例层返回 `GameError`、`WorldError`、战斗错误或其他结构化错误，不写日志或退出进程。
