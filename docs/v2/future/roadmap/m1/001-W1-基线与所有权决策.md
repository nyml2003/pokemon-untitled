# W1：基线、fixture 与所有权决策

> 归属：M1 产品会话收敛与真实战斗回写。
> 状态：已完成；记录日期：2026-07-21。
> 性质：当前代码基线加上 M1 已决定的实施边界。除“当前代码事实”外，本文不宣称目标 API 已经实现。

## 结论

M1 不新建第三个“产品状态” crate。现有 `game-session` 演进为产品会话：它协调 `GameState`、世界投影和可选的 `BattleSession`，并成为 runtime 唯一可变业务入口。`game-foundation` 保持纯粹的长期状态、静态薄切片内容、经济规则和存档 envelope；`battle-session` 保持瞬态对战执行、回放和终局观察；`game-host` 只负责装配、输入、文件 I/O 与表现，不再独立持有另一份 `FoundationState`。

这项收敛消除的不是 crate 数量，而是运行时有两份可分别变化的玩家状态。M1 后，同一份长期状态必须同时决定世界位置、队伍、金钱、背包、事件 flag、训练师完成状态和活动战斗上下文。

## 当前代码事实

| 组件 | 当前持有的关键状态 | 当前命令或输出 | 当前事实 | M1 后职责 |
| --- | --- | --- | --- | --- |
| `game-foundation::GameState` | 地图、位置、朝向、队伍、背包、金钱、flag、已击败训练师、`ActiveBattle`、遭遇历史 | `NewGame`、移动、交互、warp、遭遇、购买、`ResolveBattle`；`SaveEnvelope` | `transition` 先克隆候选状态，失败返回原状态；但战斗结果仍由摘要 `outcome/hp/pp` 注入。 | 保持长期状态和不变量；接收受验证的真实对战结果补丁。 |
| `game-session::GameSession` | `WorldApplication`、世界观察、可选 `GameBattleSession`、场景；另有 `CurrentDataSet` 和 `roster_seed` | 世界移动、战斗动作、回放推进、离开已结束战斗；`GameSnapshot` | 草丛进入 `GameBattleSession`，后者通过 `roster::demo_teams` 和 seed 构造对战；结束后只切回世界。 | 成为产品会话，唯一协调长期状态、世界和活动对战。 |
| `battle-session::BattleSession` | `BattleCoordinator`、战斗场景、回放队列、终局观察 | 合法动作、提交动作、推进回放、终局观察 | 已有确定性战斗和回放语义；没有长期状态或存档职责。 | 继续只负责瞬态对战执行与终局事实。 |
| `world-application::WorldApplication` | 世界 reducer 状态和世界观察 | 移动、朝向、世界 tick、事件/观察 | 已被 `game-session` 用于真实世界移动和遭遇触发。 | 保持世界行为与投影；不拥有玩家经济、队伍或存档。 |
| `game-host::CreatureGameApp` | `Option<GameSession>`，以及独立的 `ThinSliceContent` 和 `FoundationState` | runtime 输入、渲染、基础页操作、文件保存 | 启动时分别创建 demo `GameSession` 和 `FoundationState`，它们可各自变化。 | 只装配一个产品会话并消费其快照/事件；不直接写长期业务状态。 |

当前 `game-host` 中 `FoundationState` 与 `GameSession` 的并存，是 M1 的直接收敛对象。前者用于薄切片基础页，后者用于实际世界和战斗场景；两条路径尚未共享队伍、地图、金钱或战斗结果。

## M1 所有权决策

### 决定

1. 在 `game-session` 内实现产品会话，而不是新建第三套持久状态或把业务编排放进 `game-host`。
2. `game-session` 在 W2 增加对 `game-foundation` 的 application 层依赖，并持有一份 `GameState` 与加载后的静态内容；该依赖方向不把 runtime、窗口或资产依赖带回纯状态 crate。
3. `GameState` 是 M1 所有长期字段的唯一 owner。`BattleSession` 是活动对战期间规则状态的唯一 owner；其终局事实经 `BattleResultPatch` 一次性回写到 `GameState`。
4. `WorldApplication` 的世界运行状态与 `GameState` 的位置等长期字段在产品会话中必须有单一更新顺序和单一投影来源。W2 必须写清哪一方为持久事实、何时重建或同步世界运行态，不能在两个 reducer 中各自接受同一移动命令。
5. `game-host` 只能提交类型化产品命令、处理产品事件、在允许的安全点读写存档，以及渲染产品快照。它不得保存、变更或从两份状态拼接玩家事实。

### 不进入 M1 正式路径的现有 API

下列 API 可以在迁移期为旧测试或 demo 保留，但 M1 产品路径不得依赖：

- `GameSession::new_demo`；
- `GameSession::new(..., roster_seed)` 的 demo roster 构造语义；
- `roster::demo_teams` 与 `DemoOpponentPolicy` 作为产品队伍或对手来源；
- `GameCommand::ResolveBattle { outcome, hp, pp }` 作为产品战斗完成方式；
- `CreatureGameApp` 同时持有并分别修改 `game` 与 `foundation_state` 的装配方式。

W3 负责替换前四项在产品路径中的调用，W4 用真实终局生成 `BattleResultPatch`，W5 移除 runtime 的第二份业务状态。旧 API 的最终删除需在其所有展示和质量测试迁移后进行，避免在 M1 中无意义地破坏现有视图测试。

## 固定 M1 fixture

M1 复用现有 `ThinSliceContent::standard()` 作为唯一产品场景 fixture，并冻结下列稳定 ID 和数值。它是 W2 合同测试、W3/W4 产品会话测试和 W6 存档测试的共同输入，不允许各 crate 再各自拼装相近的地图或奖励。

| 类别 | 固定内容 | 预期作用 |
| --- | --- | --- |
| 内容版本 | `thin-slice-v3` | 作为 M1 的内容版本基线；W2 合同须显式携带版本引用。 |
| 地图 | `starting-town`，`verdant-route` | 小镇出生点 `(2, 2)`；道路出生点 `(1, 1)`；道路 index `8` 为草丛。 |
| warp | `town-to-route`，`route-to-town` | 建立小镇与道路之间的确定路线。 |
| 赠送 NPC | `professor`，flag `professor-gift-claimed` | 赠送 `starter-treecko-1` 和一份 `potion`。 |
| 玩家起始宝可梦 | 模板 `starter-treecko`，最大 HP/PP 为 `35/35` | W3 映射为真实战斗玩家队伍的 M1 最小输入。 |
| 野生战 | `route-wild`，固定遭遇 roll `7` | 胜利奖励经验 `20`、金钱 `0`；由道路草丛触发。 |
| 训练师战 | NPC `route-trainer`，训练师 `route-rival`，战斗 `route-trainer-battle` | 胜利奖励经验 `45`、金钱 `120`，且只可完成一次。 |
| 商店 | `town-mart`，`potion` 单价 `30` | 验证战斗奖励后的长期金钱和背包可保存。 |
| 初始经济 | 金钱 `200`，背包容量 `20` | 场景结束前购买一份 `potion`，预期金钱为 `290`。 |

M1 场景的稳定顺序为：新游戏，向上与教授交互，获得起始队伍，`town-to-route`，向右进入草丛，以 roll `7` 发起野生战并胜利，移动至 `route-trainer` 发起并胜利，`route-to-town`，在商店购买一份 `potion`，保存并加载。现有基础状态测试使用摘要战斗结果得到 HP/PP `28/24` 后的野生战，以及 `19/16` 后的训练师战；W3/W4 必须将这些摘要输入替换为真实 `BattleSession` 的终局事实，而不是把数值复制到新测试中。

## W2 入口条件

W2 可以开始，前提是遵守本记录的边界：

1. 合同类型放在 `game-session` 的产品编排边界，或一个仅服务该边界的 application 模块中；不进入 `game-host`。
2. `BattleStartRequest`、`ActiveBattleContext` 和 `BattleResultPatch` 只传递稳定 ID、版本、随机输入、队伍/奖励事实与 continuation，不传窗口、资产、文件句柄或模型输出。
3. 首个合同测试必须用本页 `thin-slice-v3` fixture，并覆盖未知引用、重复活动战斗和原状态不变的失败路径。
