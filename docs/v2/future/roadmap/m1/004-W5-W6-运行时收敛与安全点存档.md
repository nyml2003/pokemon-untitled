# W5/W6：运行时收敛与安全点存档

> 归属：M1 产品会话收敛与真实战斗回写。
> 状态：已完成；记录日期：2026-07-21。
> 实现位置：`game-host/src/main.rs`、`game-session::ProductSession`。

## 运行时边界

`CreatureGameApp` 在启动时创建 `ProductSession`，并默认进入 `FoundationPage::Journey`。基础页只读取 `ProductSnapshot`，并把输入转换为 `ProductCommand`：世界移动、前方交互、遭遇、前方购买、战斗动作、回放推进和离开完成战斗都由产品会话处理。前方 NPC 的位置、朝向和 capability 也由产品会话解析，host 不读取 `GameState` 或内容布局来拼装 NPC ID。基础页的“推进”操作不再提交摘要 HP/PP，而是选择 `BattleSession` 此刻允许的真实动作，或在回放锁定时推进回放，终局才提交离开战斗。

为兼容既有资产装配，启动期仍临时构造 demo `GameSession` 以取得 sprite manifest；它不会存入 `CreatureGameApp`，不进入事件循环，也不能与产品会话竞争业务所有权。旧展示分支仍保留为迁移兼容代码，但当前产品入口始终停留在产品基础页。

`product_command` 只映射正式世界命令；旧 `FoundationCommand::ResolveBattle` 被显式拒绝。对应 host unit test 固定这一约束。

## 安全点存档

`ProductSession::save` 仅在没有活动战斗时生成 `SaveEnvelope`；战斗中返回 `SaveUnavailableDuringBattle`。runtime 在写盘前完成 envelope JSON 解析和 `ProductSession::from_state` 重建，确认文件内容可以成为新的安全点状态。随后写入同目录临时文件并通过 rename 替换目标文件；写入、验证或替换失败时，内存会话与原目标文件都不被更新。

存档文件当前是 `target/foundation-page.save.json`，属于 runtime 默认文件策略而不是 `game-foundation` 的职责。`SaveEnvelope` 继续只做序列化、完整性校验和内容引用验证，不访问文件系统。

## 验证

- `ProductSession` 测试断言活动战斗拒绝保存，安全点 JSON 重载后状态完全相等；无前方 NPC 的交互和购买意图也不会改变快照。
- 完整 M1 application 场景在保存前完成赠送、野生战、训练师一次性奖励和购买，重载后比较完整 `GameState`。
- host unit test 断言运行时不会把旧摘要结算命令映射为 `ProductCommand`。

W7 只剩全 workspace 验证、文档检查和原生 host 验收；原生验收要求已同步、可构建的 Windows 镜像，不能用 WSL 无窗口测试替代。
