# W2：跨会话战斗合同

> 归属：M1 产品会话收敛与真实战斗回写。
> 状态：已完成；记录日期：2026-07-21。
> 实现位置：`crates/application/game-session/src/battle_contract.rs`。

## 已实现边界

`game-session` 现在依赖 `game-foundation`，但尚未改变既有 demo `GameSession` 的运行路径。新增的合同类型位于 `game-session` 的私有 `battle_contract` 模块，并由 crate 根逐项导出：

| 类型 | 责任 | 受约束的事实 |
| --- | --- | --- |
| `BattleSource` | 区分野生与训练师来源 | 野生遭遇 roll；训练师 NPC ID 和训练师档案 ID。 |
| `BattleContinuation` | 定义战斗结束后回到哪里 | 地图 ID 与位置。 |
| `BattleStartRequest` | 冻结开战输入 | 内容版本、战斗 ID、来源、持久队伍快照、参与者、随机 seed 与 continuation。 |
| `ActiveBattleContext` | 防止同一产品会话出现第二场活动战斗 | 一个已验证的 `BattleStartRequest`。 |
| `BattleParticipantPatch` | 表达当前 M1 可保存的单个参战者结果 | 宝可梦 ID、HP、PP。 |
| `BattleResultPatch` | 把终局事实组织为可在 W4 原子应用的补丁 | 内容版本、战斗 ID、胜负、参与者更新、经验、金钱、已击败训练师和 continuation。 |

`BattleResultPatch` 的奖励来自 `ThinSliceContent` 中对应的 `BattleDefinition`，不接受 presentation 或模型给出的金钱、经验、训练师完成标记。失败时补丁奖励为零且不完成训练师。

## 构造期验证

`BattleStartRequest::new` 与 `BattleResultPatch::from_context` 在创建边界检查：

1. battle、NPC、训练师、地图和宝可梦模板引用存在。
2. 野生 roll 位于 `0..=99`；野生来源不得引用训练师战，训练师来源必须同时匹配 battle 定义中的 NPC。
3. 队伍非空，成员 ID 不重复，参与者确实来自该队伍，队伍快照与模板 HP/PP 上限一致。
4. continuation 的位置在目标地图内。
5. 结果补丁的内容版本与发起请求一致，终局 HP/PP 不超过参与者模板上限。
6. 已有 `ActiveBattleContext` 时拒绝第二次 `begin`，且不改变原上下文。

错误均为 `BattleContractError` 的类型化分支；没有字符串命令、隐式 demo seed、窗口对象、资产、文件句柄或模型输出进入合同。

## 固定场景验证

新增的 `game-session` 合同测试复用 W1 固定 fixture：

| 场景 | 断言 |
| --- | --- |
| `route-wild`，roll `7` | 请求保存 `thin-slice-v3`、显式参与者和 seed；胜利补丁为 HP/PP `28/24`、经验 `20`、金钱 `0`。 |
| `route-trainer-battle` | 训练师来源必须对应 `route-trainer` 与 `route-rival`；胜利补丁为经验 `45`、金钱 `120`、完成 `route-trainer`。 |
| 拒绝路径 | 第二场活动战、HP `36`、roll `100` 均被拒绝，原活动上下文不变。 |
| 未知引用 | 缺失 battle 或 NPC 在请求构造期被拒绝。 |

## 明确未实现项

W2 只建立数据合同，未执行以下行为：

- 未从 `CreatureState` 或 `TrainerDefinition` 构造 `battle-application::Team`；这属于 W3。
- 未让现有 `GameSession` 持有 `GameState`，未替换 `roster::demo_teams`，未接入 host。
- 未将 `BattleResultPatch` 应用到 `GameState`，也未删除 `ResolveBattle`；这属于 W4。
- 未保存活动战斗，也未加入状态异常、多成员映射、AI 对手或模型调用。

## 验证结果

已通过 `ops format --check`、`ops lint` 和 `ops test --suite core`。core suite 的 `game-session` 现有 12 项测试与新增 4 项合同测试均通过，共 16 项。

W3 的入口是：以这些请求类型作为唯一产品开战输入，建立从 `GameState` 和内容定义到真实 `BattleSession` 的映射；不得绕过合同继续从 `roster_seed` 创建产品队伍。
