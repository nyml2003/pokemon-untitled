# 图鉴横向深入与视差转场

> 分类：未来；起草：2026-07-26。
> 状态：表现层实施计划。本文不表示功能已经实现。

## 结论

图鉴不再是一个固定的“双栏页面”。它改成一条横向深入的页面轨道：

```text
列表  <---->  宝可梦详情  <---->  种族值分析  <---->  技能列表
  0              1                 2                 3
```

玩家用键盘左右键切换层级，用上下键操作当前层级内的列表。切换时页面连续移动，当前层级占据主视区，相邻层级只保留很小的视觉提示。鼠标只负责有限的点击和焦点定位，不承担主要导航职责。

这次工作的重点不是再堆一套装饰面板，而是把“页面深度”变成表现层和输入层都能理解的基础概念。图鉴页面仍然从 `game-page-model` 读取数据，不能在 `game-view` 中复制一份页面状态。

## 设计原则

### 1. 世界画面保持沉浸

- 世界探索画面不放固定 HUD。
- 图鉴的视差、标题、焦点和页面轨道只存在于图鉴页面。
- 打开图鉴后可以有页面过渡，但不能把世界 HUD 偷渡到世界场景。

### 2. 视觉引导优先于说明文字

- 不使用“暂停”“返回”“下一页”这类固定文字作为主要导航控件。
- 用入口贴图、当前焦点、相邻页面露出和空间方向表达页面关系。
- 左右边界只在确实有下一层或上一层时显示视觉暗示。
- 键位说明单独写入操作文档或开发验收文档，不把说明文字塞进游戏画面。

### 3. 键盘是主输入

```text
上下       当前列表移动一项
Home/End   当前列表跳到首项/末项
左         进入上一层
右         进入下一层
确认       打开当前条目或确认当前动作
取消       关闭当前页面或回到上一级页面合同
```

- 左右键只改变图鉴层级，不改变当前宝可梦的事实数据。
- 进入详情、种族值、技能列表时，保留当前选中的宝可梦。
- 从技能列表回到种族值时，保留当前技能选中项；从种族值回到详情时，保留详情焦点。
- 点击某个条目后，键盘上下移动必须从点击后的索引继续，而不是从点击前的索引继续。
- 不新增独立的“返回按钮”。取消键和左键负责返回，具体行为由页面导航合同决定。

### 4. 页面是游戏页面，不是数据后台

- 数值可以有条形图和六边形图，但它们必须服务于比较和识别。
- 图标、宝可梦立绘、类型图标和状态素材作为视觉锚点。
- 资源不足时保留清晰的占位槽位，不能用大量技术标签伪装成完成的游戏 UI。
- 现有资源可以先接入。新素材只补内容表现，不改变页面层级合同。
- 专门为页面制作的宝可梦表现素材应设计成可复用资源，详情页、列表焦点和后续队伍页可以共享。

## 页面结构

### 逻辑层级

```text
PokedexSection::Index
  └─ 选择宝可梦
       -> PokedexSection::Detail
            ├─ 概览、立绘、类型、描述
            -> PokedexSection::Stats
                 ├─ 六项种族值条形图
                 └─ 六边形网状图
            -> PokedexSection::Moves
                 └─ 技能列表、类别图标、威力、命中、PP
```

### 视觉轨道

```text
屏幕坐标
0%                 50%                                  100%
|-------------------|--------------------------------------|
       上一层提示      当前层级主视区       下一层提示

轨道位置：   -1.0       0.0       1.0       2.0       3.0
页面层级：    列表       详情      种族值      技能
```

图鉴轨道按轮播卡片组织四个页面：当前页面居中，卡片宽度约为视口的 78%，相邻卡片沿轨道保留约 20% 的可见边缘，远侧卡片通过遮罩降低存在感。页面切换时四张卡片连续移动，形成轻量的 3D 深度感；这不是把一张全屏页面简单平移。

每张卡片内部仍使用背景、结构、内容三种不同的视觉位移速率。虚拟列表只对当前层的列表内容进行窗口化，邻近卡片只提供视觉预览。INDEX 只展示居中的列表主体，DETAIL 才使用 front 大图，避免相邻页面重复展示同一个主体。

动画期间允许准备目标层，但不能让不可见页面的点击区域覆盖当前页面。

### 页面文件拆分

`game-view/src/page/pokedex.rs` 应拆成按页面职责组织的目录：

```text
crates/presentation/game-view/src/page/pokedex/
├── mod.rs       图鉴入口、公共类型和页面拼装
├── index.rs     图鉴列表、筛选焦点、左侧虚拟滚动
├── detail.rs    宝可梦概览、立绘、类型和说明
├── stats.rs     条形图、六边形图、种族值比例
├── moves.rs     技能列表、技能类别图标和右侧虚拟滚动
└── motion.rs    轨道位置、视差层和页面绘制参数
```

拆分规则：

- `mod.rs` 只保留根级组合和逐项导出。
- 页面子模块默认私有，不把实现路径变成公共 API。
- 页面渲染函数接收 `PokedexPageModel` 和只读表现参数。
- 页面子模块不能各自保存选中索引、技能列表或统计值。
- 图鉴之外的 `page.rs` 继续只负责页面路由和公共页面组合。

## 状态合同

### 页面层级

在 `game-page-model` 增加明确的图鉴层级类型，例如：

```rust
pub enum PokedexSection {
    Index,
    Detail,
    Stats,
    Moves,
}
```

该类型表示玩家正在查看的页面层级，不表示动画进度。动画进度属于表现层状态，不能写入产品事实模型。

需要保持的现有数据：

- `selected`：当前宝可梦。
- `selected_move`：当前技能。
- `detail_view`：概览/技能的已有兼容状态，迁移时应逐步收敛到 `PokedexSection`。
- `stats_view`：条形图/六边形图。
- `entries`、`moves`：页面数据和数量。

迁移期间可以保留现有 intent，新增层级 intent 时必须保证根级路径稳定。最终建议将左右键表达成 UI 导航结果，而不是伪造产品命令：

```text
PageUiState + PageModel
    -> PageUiOutcome::NavigatePokedex(section)
    -> 更新 UI 焦点和表现层动画目标
```

如果现有 `PageIntent::SelectPokedexDetail` 足以表达业务状态，则不为动画单独增加产品 intent。动画不应触发存档、战斗或世界状态变更。

### UI 焦点

`game-ui` 需要把焦点从“页面类型 + 索引”提升为“图鉴层级 + 层级焦点”。目标是让以下状态可直接表达：

```text
当前层级：Moves
当前技能：index = 4
目标层级：Stats
动画状态：从 Moves 向 Stats 移动，进度 0.35
```

焦点更新顺序必须固定：

1. 先根据鼠标点击或键盘动作确定新的逻辑焦点。
2. 再根据新的逻辑焦点计算虚拟滚动窗口。
3. 最后设置视差动画目标。

这样可以避免点击后的索引被旧焦点覆盖，也避免动画进度影响列表选择。

## 底层表现能力

### `punctum-ui` 增加节点级视觉偏移

当前 `UiPixelOffset` 主要服务于图片内容。图鉴需要对整组节点做横向位移，因此应在 `UiStyle` 增加节点级视觉偏移，名称可以是 `visual_offset` 或等价 API。

约束如下：

- 偏移只改变绘制边界、裁剪边界、鼠标命中区域和交互目标。
- 偏移不改变节点在父容器中的布局占位，不触发重新排版。
- 父节点偏移必须传递给子节点。
- 偏移后的节点仍受父级 clip 限制。
- 当前非活动页面的 action hit 和 interaction target 必须被禁用或裁剪。
- 支持负向偏移，避免向左移动时发生整数溢出。
- 不要求 `game-native-plan` 新增特殊渲染路径；它继续消费解析后的 `UiFrame`。

推荐的解析顺序：

```text
布局计算原始 bounds
    -> 累积父子 visual_offset
    -> 计算绘制 bounds 与 clip
    -> 计算 action hit / interaction target
    -> 输出 UiFrame
```

不要通过改变 `UiStyle.width` 或 `margin` 模拟动画。那会让列表布局、命中区域和虚拟滚动互相影响。

### 视差层

图鉴页面使用三层轻量视差：

```text
背景层       35% 轨道位移，只有纹理或色块层
结构层       65% 轨道位移，页面容器和边框
内容层      100% 轨道位移，列表、立绘和图表
```

- 视差只提供空间方向，不添加发光球、渐变球或装饰性背景。
- 背景层不能抢过宝可梦立绘和当前焦点。
- 轨道位移以整数像素输出，保持像素画边缘稳定。
- 页面内容使用现有 UI 样式和资源，不把风格化素材嵌入通用 UI 组件。

### 动画状态

`game-ui` 保存逻辑焦点，`game-view` 或独立的表现层状态保存动画进度。建议使用固定点或整数毫单位表达轨道位置，避免浮点累积误差：

```text
current_position : 0..3000
target_position  : 0..3000
velocity/easing  : 表现层参数
```

动画要求：

- 左右键切换目标层级时连续移动。
- 新输入可以中断当前动画，并从当前视觉位置追踪新的目标。
- 目标层级到达后，只有当前层保留完整交互。
- 动画期间不改变宝可梦和技能的逻辑选中项。
- 默认转场时长控制在 150~300ms；具体值以 demo 手感为准。
- 后续如需减少动效，应能将动画直接退化为一次性位置更新。

## 虚拟列表与性能

图鉴列表和技能列表继续使用虚拟滚动，但窗口属于当前页面层级，不属于整个横向轨道。

实现要求：

- 保留屏幕内项目和少量屏幕外预渲染项目。
- 上下键每次移动一个逻辑索引。
- 快速连续输入时合并无效中间绘制，但不能跳过最终焦点。
- 当前项目尺寸先按可读性重新标定，精灵图标使用 icon 资源，详情页才使用 front 资源。
- 预渲染窗口变化不应造成父容器宽高变化。
- 统计每帧 UI 构建、布局解析、绘制命令数量和虚拟列表重建数量；指标默认打印到 log 和退出报告，不放到游戏画面。

性能验收重点：

```text
普通上下移动       不出现可见跳帧
连续上下输入       不产生无界队列
左右转场           不重复构建四个完整页面
技能列表长窗口     只构建可见范围及预渲染范围
鼠标点击后上下键   从点击索引继续移动
```

## crate 影响范围

### 必须修改

| crate | 修改内容 | 原因 |
| --- | --- | --- |
| `punctum-ui` | 节点级视觉偏移、累积偏移、clip 和命中测试 | 视差必须作用于整组 UI 节点，不能由上层拼接每个子节点的位置。 |
| `game-page-model` | 图鉴层级类型和迁移所需的页面状态合同 | 页面层级必须是可测试的状态，而不是 renderer 私有枚举。 |
| `game-ui` | 图鉴层级焦点、左右导航、点击后焦点同步、动画目标 | 键盘输入和逻辑焦点属于 UI 状态。 |
| `game-view` | `page/pokedex/` 目录、四层页面投影、视差参数和虚拟列表接入 | 负责把模型投影为游戏画面。 |
| `game-page-demo` | 驱动 UI 动画 tick、请求重绘、切换 demo 页面并输出性能指标 | 先在 demo 完成视觉和输入验收。 |

### 视实现需要修改

| crate | 触发条件 | 处理原则 |
| --- | --- | --- |
| `game-ui-kit` | 需要共享页面轨道、焦点框或像素容器时 | 只抽取无业务含义的基础组件，不把图鉴层级塞入 kit。 |
| `game-native-plan` | 仅当现有 `UiFrame` 无法表达新的裁剪或命中语义时 | 优先保持它只做 `UiDrawCommand` 到 native plan 的转换。 |
| `game-native-target` | 仅当窗口重绘调度无法支持动画帧时 | 只补重绘触发，不在 target 层保存图鉴状态。 |
| `game-host` | 正式项目接入 demo 验收后的图鉴页面时 | 第二阶段处理，不能让 demo 先反向污染正式产品会话。 |
| `game-assets` | 接入新的图标、立绘或状态素材时 | 先补资源 manifest 和占位槽位，不把素材路径硬编码到页面逻辑。 |

当前不需要修改 `punctum-gpu`。只要 `UiFrame` 输出了正确的 bounds、clip 和命中区域，GPU 层无需知道视差页面的业务含义。

## 实施顺序

### 阶段一：冻结状态和验收样本

- 增加 `PokedexSection` 或等价层级合同。
- 为四个层级建立固定 demo fixture。
- 明确列表、详情、种族值、技能的逻辑焦点。
- 为重复 key、空数据、未知资源和边界索引补测试。

完成标准：不做动画时，左右键可以稳定切换四层，上下键和点击焦点行为正确。

### 阶段二：拆分图鉴投影

- 将 `page/pokedex.rs` 拆到 `page/pokedex/`。
- 保持现有根级投影入口和测试调用方式。
- 将列表、详情、种族值、技能的资源选择分别收口。
- 统一生成 UI key，确保每个页面实例中的 key 唯一。

完成标准：拆分前后页面数据、资源、统计图和技能类别图标一致；不出现 `UiKey` 重复。

### 阶段三：实现基础视觉偏移

- 在 `punctum-ui` 增加节点级 `visual_offset`。
- 为 bounds、clip、action hit 和 interaction target 建立单元测试。
- 验证负向偏移、嵌套偏移、边界裁剪和偏移后点击区域。
- 保证不改变正常布局流和虚拟列表测量。

完成标准：一个通用容器可以整体横向移动，子节点和交互区域跟随，父级裁剪仍然正确。

### 阶段四：接入三层视差和可中断转场

- 在 `game-ui` 生成当前轨道位置和目标轨道位置。
- 在 `game-view` 将轨道位置映射到三层偏移。
- 在 `game-page-demo` 按 redraw tick 推进动画。
- 新的左右输入从当前视觉位置追踪新目标。
- 动画中只有当前逻辑层接受交互。

完成标准：连续左右切换没有跳回、闪烁或点击穿透；快速来回操作最终停在最后一个目标层级。

### 阶段五：补齐资源和正式接入

- 先使用现有宝可梦、类型、技能类别和图鉴资源。
- 缺失资源继续使用明确的占位槽位。
- 视觉验收通过后，再将相同的页面组合接入正式 `game-host`。
- 正式接入时重新核对世界画面无固定 HUD，且页面关闭仍遵守产品导航合同。

完成标准：demo 和正式项目共用页面模型、页面投影和输入合同，不复制一套 renderer 私有图鉴逻辑。

## 测试与验收

### `game-page-model`

- 四个 `PokedexSection` 的顺序和边界。
- 保留 `selected` 和 `selected_move` 的导航行为。
- 空技能列表、未知宝可梦和末项索引不 panic。

### `game-ui`

- 左右键分别进入上一层和下一层。
- 上下键只移动当前列表。
- 鼠标点击后，上下键从点击项的索引继续。
- 动画进行时的新方向会更新目标，不恢复旧目标。
- 非当前层级不产生可提交的 action。

### `punctum-ui`

- 节点级偏移不改变布局尺寸。
- 子节点继承父偏移。
- clip 对偏移后的绘制命令和命中区域仍生效。
- 负向偏移不会溢出或产生错误命中。

### `game-view`

- 四个层级均能生成非空 UI 树。
- 资源路径和资源类型正确：列表 icon，详情 front，技能类别使用对应图片。
- 统计条比例以 256 为满格，六边形图使用 50、100、150 三个同心六边形，并允许数据多边形超出 150 环。
- page key 在同一 UI 树内唯一。

### `game-page-demo`

- 可以从 demo 入口直接打开图鉴并切换四个层级。
- 只用键盘完成浏览，不依赖前后翻页按钮。
- 连续转场和快速反向输入可观察。
- 性能指标仍输出到 log 和退出报告，不覆盖游戏画面。
- 视觉检查覆盖普通窗口和较小窗口，确认文本、图标、立绘、图表不互相遮挡。

## 非目标

- 本计划不改世界场景的 HUD。
- 本计划不增加鼠标优先的分页按钮、返回按钮或固定导航栏。
- 本计划不在 `game-native-plan` 中实现图鉴业务逻辑。
- 本计划不要求一次性补齐所有专用精灵表现素材。
- 本计划不把像素风格纹理、宝可梦立绘或背包参考图硬编码进通用 UI 基础组件。
- 本计划不承诺使用 shader 渲染页面转场；先用 `UiFrame` 的 bounds/clip 和稳定的像素偏移完成可验证版本。

## 决策记录

本计划采用以下默认决策：

| 问题 | 决策 |
| --- | --- |
| 页面组织 | 列表 -> 详情 -> 种族值 -> 技能列表的横向深入。 |
| 视觉重点 | 当前层级占主视区，相邻层级只露出小范围提示。 |
| 输入 | 键盘左右切层，上下移动列表，鼠标有限支持。 |
| 返回 | 不增加可见返回按钮；使用取消键和左键。 |
| 动画 | 连续移动，默认 150~300ms，可中断并追踪新目标。 |
