# 玩家界面视觉与交互结构

> 分类：未来；起草：2026-07-25。
> 状态：玩家页面占位批次已接入 game-page-demo；正式 game-host 接入、skin、动效和正式素材仍未完成。

## 结论

当前 game-view 的主要问题不是缺少像素边框，而是把不同性质的画面都做成了同一种页面：

- 世界探索被做成带状态栏的页面。
- 导航被做成标题加文字列表。
- 详情被做成信息卡。
- 战斗被拆成多个相似但不一致的投影路径。
- 键位、页面结构、视觉资源和动效没有清楚分开。

新的方向是先定义玩家如何看见和操作画面，再决定 UI 资源长什么样：

~~~text
游戏状态
    |
    v
当前画面模式
世界 / 导航 / 详情 / 战斗
    |
    v
视觉构图
贴图、位置、焦点、状态条、必要文字
    |
    v
表现资源
像素边框、字体、图标、纹理、动效
~~~

先在 game-page-demo 中验收这套结构。正式 game-host 暂不接入 demo 的页面状态和 fixture。

## 一、问题和目标

### 1. 当前问题

当前页面把“说明自己是什么”当成了主要任务，所以画面里出现了大量标题、按钮和状态文字。玩家看见的是一个管理面板，而不是一个正在运行的游戏。

这会产生三个后果：

1. 世界画面持续被 HUD 抢走注意力。
2. 导航页面依赖文字才能识别入口，贴图和角色没有发挥作用。
3. 所有页面共享相同的卡片结构，队伍、背包、图鉴和战斗失去自己的阅读节奏。

### 2. 目标体验

| 画面模式 | 玩家首先看见什么 | 主要操作 |
| --- | --- | --- |
| 世界 | 地图、角色、NPC 和正在发生的事件 | 移动、观察、交互 |
| 导航 | 队伍、背包、图鉴、训练家卡的视觉入口 | 移动焦点、进入页面 |
| 详情 | 当前选中的宝可梦、物品或图鉴条目 | 查看、使用、切换 |
| 战斗 | 双方宝可梦、状态和当前命令 | 选择并提交命令 |

每个画面都必须先回答两个问题：

- 玩家现在应该看哪里？
- 玩家现在可以做什么？

## 二、设计原则

这些原则同时约束画面构图、输入、资源、动效和工程接入。

1. **先解决构图，再解决装饰。** 先确定视觉焦点和操作焦点，再决定边框、颜色、字体和像素素材。
2. **世界探索默认零 HUD。** 地图和角色占据完整画面。不显示常驻地点栏、队伍摘要、菜单按钮或底部操作栏。
3. **视觉引导优先于标题解释。** 页面不依靠“暂停”“背包”“图鉴”等大标题说明状态。入口使用角色、物品、图鉴和卡片贴图区分。
4. **焦点优先于文字。** 当前选择用位置、放大、描边、明暗、状态条或动效表达。文字只补充贴图不能表达的信息。
5. **页面不能变成管理后台。** 不使用通用的“标题 + 信息卡 + 按钮”覆盖所有页面。每个页面保留自己的主要任务和阅读顺序。
6. **游戏美术和 UI 语义分离。** 页面只声明宝可梦贴图、物品贴图、图标、状态条等语义资源槽位，不声明某个具体边框或色板。
7. **键盘是完整的主要操作路径。** 所有核心流程都能只用键盘完成。键位单独定义为语义动作，并支持重映射。
8. **返回是状态转换，不是可见控件。** 页面不显示返回按钮。取消动作负责关闭提示、取消选择和回到上一级状态。
9. **鼠标只做有限辅助。** 鼠标可以悬停移动焦点、左键确认，但不能成为核心流程的必要条件，也不引入第二套页面结构。
10. **动效不能拯救静态构图。** 关闭动效后，所有重要信息和操作状态仍然可读。
11. **先在 demo 验收，再接入正式项目。** demo 负责验证构图、输入路径和资源槽位。正式项目只接入已接受的结构。
12. **不把单页风格抽象成全局模板。** 一个页面的有效设计可以影响其他页面，但不能直接规定其他页面必须使用同样的轨道、网格、卡片或动效。

### 参考图的使用边界

assets/other/DP背包.png 首先是背包页面的直接参考。它帮助确定背包的图标轨道、物品袋网格、贴图选中态和局部提示。它不是整套玩家界面的统一模板。

其他页面只在确实解决问题时借鉴其中的一部分：

| 页面 | 可以借鉴的部分 | 不强行复制的部分 |
| --- | --- | --- |
| 暂停导航 | 入口贴图、焦点放大 | 不必使用物品袋网格，也不必放置顶部分类条 |
| 队伍 | 大号角色贴图、局部状态反馈 | 不必使用物品袋、数量角标或分类过滤 |
| 图鉴 | 剪影、贴图变体、发现状态纹理 | 不必使用背包的密集排列，识别顺序优先于扫描速度 |
| 战斗 | 命令图标、选中态、局部消息 | 不必使用背包式网格，战场位置和状态窗口优先 |
| 世界探索 | 临时事件中的贴图反馈 | 不使用常驻图标轨道、网格 HUD 或分类条 |

每个页面仍然需要单独回答：它的主要视觉焦点是什么、玩家如何移动焦点、信息应该连续展示还是按事件出现。借鉴参考图不能替代这些判断。

## 三、画面模式

### 1. 世界模式

世界模式不显示常驻 HUD。玩家通过地图、角色、NPC、可交互对象和事件动画获得信息。

~~~text
+------------------------------------------------------+
|                                                      |
|                    地图 / 角色 / NPC                 |
|                                                      |
|                                                      |
|                                                      |
|                                                      |
+------------------------------------------------------+
~~~

世界模式只允许三类临时反馈：

~~~text
普通探索：                    无 HUD

靠近交互对象：                对象附近出现短暂提示
                              [局部交互贴图]

获得物品或触发事件：          画面边缘短暂出现反馈
                              [物品贴图]  +1
~~~

临时反馈不能形成固定面板，不能遮挡角色和交互对象，也不能在没有事件时留下空白占位。

### 2. 导航模式

导航模式是视觉入口集合，不是写满页面名称的菜单。四个入口使用四种可识别贴图：

- 队伍：宝可梦缩略图或队伍徽记。
- 背包：物品袋、道具轮廓或物品分类贴图。
- 图鉴：图鉴封面、书页或宝可梦剪影。
- 训练家卡：角色头像、徽章或卡片纹理。

ASCII 图中的 [asset] 代表贴图槽位，不代表实际渲染文字。

~~~text
+------------------------------------------------------+
|                                                      |
|       [asset]       [asset]       [asset]       [asset]|
|          ^                                           |
|                                                      |
|                 +------------------+                 |
|                 |                  |                 |
|                 |      [asset]     |     [detail]    |
|                 |   [status bars]  |                 |
|                 +------------------+                 |
|                                                      |
+------------------------------------------------------+
~~~

当前焦点用放大、描边、明暗差、背景纹理或轻微动效表达。入口不固定显示文字标签；如果贴图仍然有歧义，标签只在焦点移动后短暂出现，或放在当前详情区域。

### 3. 详情模式

详情模式只围绕一个对象组织。左侧或上方负责快速扫描，主区域负责展示当前对象。标题不是必需的视觉入口。

#### 队伍

队伍页面的重点是“从队伍中选中一只宝可梦”。会展示宝可梦状态，但按阅读距离分层：

- 队伍格子只展示贴图、HP 条和必要的不可用状态。
- 当前焦点展示大贴图、名称、HP、PP 和经验进度。
- 异常状态只在确实存在时显示图标，不为没有状态的宝可梦预留一排文字。
- 等级、属性和异常状态只有在对应领域数据进入 PageModel 后才能接入，不在当前设计中伪造。

当前 PartyMemberModel 已有 current_hp、max_hp、current_pp、max_pp 和 experience。因此 HP、PP 和经验条属于当前可落地内容；等级和状态图标属于后续资源槽位。

~~~text
+------------------------------------------------------+
|                                                      |
| > [asset]   [asset]   [asset]   [asset]   [asset]    |
|   [hp bar]  [hp bar]  [hp bar]  [hp bar]  [hp bar]   |
|   [state]   [state]   [state]   [state]   [state]    |
|                                                      |
|                    +----------------+                |
|                    |                |                |
|                    |    [asset]     |   [hp bar]     |
|                    |   [pp bar]     |   [exp bar]    |
|                    |   [state icon] |                |
|                    +----------------+                |
|                    [name / small text]               |
+------------------------------------------------------+
~~~

HP 条是队伍扫描时的主状态信号。当前焦点附近可以显示名称和数值，但队伍列表不写成一列完整名称，也不同时展开六只宝可梦的完整数值。

#### 背包

背包页面参考 assets/other/DP背包.png 的构图：顶部是一条密集的分类图标轨道，主体是规则的物品袋贴图网格。它不是文字列表，也不默认放置右侧详情卡。

参考图提供三个需要保留的结构：

1. 顶部小图标负责快速切换物品语义组。
2. 主体网格使用大号物品袋贴图，贴图本身承担识别工作。
3. 选中态使用颜色、纹理和图标变化表达，不靠一行“当前选中”文字。

参考图中的蓝色背景、金色边框和具体袋子素材属于 skin 参考，不直接写入页面语义。demo 可以先使用这张图做占位和裁切实验，正式资源仍通过资源槽位接入。

分类采用横向图标轨道，不打开第二层分类页面。第一版直接映射当前领域模型已有的三类，并保留一个全部视图：

~~~text
 [all] [medicine] [key] [general] [future slots ...]
    ^       |        |       |
    +-------+--------+-------+------ 只过滤主体网格
~~~

实际界面不固定写出“全部、药品、关键物品、一般物品”等长标签。每个分类使用稳定的贴图或图标，当前分类通过底纹、颜色、描边和数量标记表达；焦点停留在分类图标上时，才短暂显示名称。

分类行为：

- Q 切换到上一个分类，E 切换到下一个分类。
- 方向键或 WASD 继续移动当前分类内的物品焦点。
- Z 或 Enter 确认当前物品。
- 切换分类不离开背包，不重置页面布局。
- 当前物品仍属于新分类时保留焦点；不属于时选中该分类的第一个物品。
- 空分类显示分类贴图的空状态，不显示占满画面的“没有物品”说明。
- 分类内保持稳定顺序，不因切换分类临时按名称重排。
- 物品网格保持固定列数和格子尺寸，分类切换不能让贴图跳位。
- 数量显示在物品袋贴图的固定角落，不单独占一列。
- 确认物品时，只在当前格子附近显示名称、效果和可用动作，不展开永久详情面板。

~~~text
+------------------------------------------------------+
| [i] [i] [i] [i] [i] [i] [i] [i] [i] [i] [i] [i]     |
+------------------------------------------------------+
|                                                      |
| > [bag]   [bag]   [bag]   [bag]   [bag]              |
|   [qty]   [qty]   [qty]   [qty]   [qty]              |
|                                                      |
|   [bag]   [bag]   [bag]   [bag]   [bag]              |
|   [qty]   [qty]   [qty]   [qty]   [qty]              |
|                                                      |
|                 [local item notice]                  |
+------------------------------------------------------+
~~~

默认焦点在主体网格，不在分类轨道。Q/E 直接切换分类；从网格向上移动可以进入分类轨道，再用左右键精确选择分类，向下回到网格。

物品名称和说明不在所有格子中重复显示。当前焦点的物品只在贴图附近出现局部提示；确认后再显示使用、丢弃或查看等动作。没有选中物品时，画面不保留空的说明区域。

#### 图鉴

图鉴页面的重点是识别和比较。已发现条目使用完整贴图，未发现条目使用剪影、噪点或封面纹理；两者使用同一位置关系。

~~~text
+------------------------------------------------------+
|                                                      |
| > 001 [silhouette]     002 [asset]     003 [silhouette]|
|   004 [asset]          005 [asset]     006 [unknown]  |
|                                                      |
|                    +----------------+                |
|                    |                |                |
|                    |    [asset]     |                |
|                    |   [type marks] |                |
|                    |   [seen state] |                |
|                    +----------------+                |
+------------------------------------------------------+
~~~

编号可以保留，因为它是图鉴的识别信息；名称、属性和说明只在当前条目中出现。

### 4. 战斗模式

战斗需要 HUD，但 HUD 服务于战斗状态，不服务于页面标题。双方状态窗口贴近对应宝可梦，命令使用图标和位置表达，消息窗口只在需要传达事件时出现。

~~~text
+------------------------------------------------------+
| [enemy status]                         [enemy asset]  |
|                                                      |
|                                                      |
| [player asset]                         [player status]|
|                                                      |
+------------------------------------------------------+
| [message texture]                  [fight] [party]   |
|                                    [bag]   [run]     |
+------------------------------------------------------+
~~~

命令图标可以在焦点附近显示短文本，但不把四个命令做成长文字按钮。战斗只保留一套语义 HUD，当前 projection.rs 中的两条战斗投影路径必须先收敛到这套结构。

## 四、键位和状态转换

键位单独定义，不写进页面标题、按钮或 HUD。实现绑定语义动作，不直接把物理按键写进 projection.rs。

### 默认键位

| 语义动作 | 默认键位 | 作用 |
| --- | --- | --- |
| 移动 / 移动焦点 | WASD 或方向键 | 世界中移动角色；页面中移动焦点 |
| 确认 / 交互 | Z 或 Enter | 交互、进入、使用、提交命令 |
| 取消 | X 或 Esc | 关闭临时提示、取消选择、进入上一级状态 |
| 打开导航 | Tab | 世界模式进入导航模式 |
| 打开保存 | F5 | 世界模式打开保存确认；不渲染常驻保存按钮 |
| 切换背包分类 | Q / E | 切换上一个或下一个分类 |

Z 和 Enter 是同一个确认动作。X 和 Esc 是同一个取消动作。重映射只改变绑定，不改变语义。

### 状态转换

~~~text
世界模式 --Tab--> 导航模式 --确认--> 详情模式
世界模式 --确认--> 临时交互反馈
详情模式 --取消--> 导航模式 --取消--> 世界模式
确认提示 --取消--> 原模式
战斗命令 --取消--> 当前战斗子选择
~~~

### 鼠标边界

- 悬停可操作贴图时，可以移动键盘焦点。
- 左键可以确认当前焦点。
- 鼠标不提供返回按钮、拖拽导航或依赖滚轮的核心操作。
- 鼠标没有目标时，键盘焦点不改变。

## 五、表现层边界

~~~text
产品状态 / PageModel / BattleSession
                    |
                    v
             画面模式选择
        世界 / 导航 / 详情 / 战斗
                    |
                    v
             语义构图层
        贴图槽位、列表、状态条、消息、命令
                    |
                    v
                 HUD skin
       边框、字体、纹理、图标、资源变体
                    |
                    v
            Motion presentation
       焦点变化、进入退出、提示反馈、战斗 cue
~~~

### projection.rs 的职责

projection.rs 只负责：

- 根据 PageModel 或 BattleSession 选择画面模式。
- 组织语义区域和资源槽位。
- 提供当前焦点、可用状态和必要文字。
- 把状态变化转换为 presentation 事件。

projection.rs 不负责：

- 为每个页面写一套标题、卡片和返回按钮。
- 直接决定像素边框、色板、纹理和动画时长。
- 把物理按键写入页面节点。
- 为了 demo 截图伪造正式产品状态。

### 资源和 skin 的职责

skin 可以替换像素字体、边框、纹理、图标和选择状态，但不能改变页面语义。页面请求“队伍入口贴图”或“当前焦点状态”，skin 决定它具体长什么样。

世界模式默认不加载常驻 HUD skin。临时反馈只加载必要的局部资源。

## 六、素材缺口与交付格式

### 当前已有素材

以下素材已经在仓库中，不需要重复寻找：

- 地图 tile：assets/source/map/tile/
- 角色行走图：assets/source/character/
- 宝可梦图标、正面图和背面图：assets/source/pokemon/
- 战斗属性图标：assets/source/ui/battle/type/
- 招式类别图标：assets/source/ui/battle/move-category/

当前 Treecko 已有图标、正面图和背面图资源。`game-page-demo` 已先接入角色正面帧、队伍 Treecko 正面图和图鉴 Treecko 正面图；缺少对应资源的条目继续使用占位槽位。

### P0：背包 Demo 必需素材

- 分类图标：全部、药品、关键物品、一般物品，至少 4 个。
- 物品图标或物品袋贴图：伤药、精灵球、关键道具、技能机器等，至少 8 个。
- 空物品槽或空分类状态。
- 普通、选中和不可用的物品贴图变体，或者一套可以由 skin 叠加的状态纹理。

第一版只需要让分类轨道和物品袋网格看起来完整，不要求覆盖全部物品。当前领域数据只有 potion，因此 demo 可以先使用固定 fixture 展示多个分类。

### P1：页面入口和状态素材

- 队伍入口图标。
- 背包入口图标。
- 图鉴入口图标。
- 训练家卡入口图标。
- 中毒、睡眠、麻痹、烧伤、冰冻、濒死等状态图标。
- 不可用、锁定、未知、已发现等状态纹理。

HP、PP 和经验条由程序绘制，不需要寻找整条图片。

### P2：战斗素材

- 战斗、宝可梦、背包、逃跑四个命令图标。
- 战斗消息框纹理。
- 战斗状态窗口纹理。
- 战斗选择焦点或命令选中态。

战斗属性图标和招式类别图标已经存在，可以继续复用。

### 素材交付格式

- 使用透明背景 PNG，避免把背景色、文字和选中框烘焙进素材。
- 推荐以 32x32 或 64x64 为基础尺寸，使用整数倍缩放。
- 单个图标优先；使用 sprite sheet 时同时提供格子尺寸、帧顺序和裁切说明。

## 七、Demo 验收

game-page-demo 是视觉和输入验收场，不是第二套游戏逻辑。它可以使用固定 fixture，但不执行正式产品效果，也不写存档。

| 场景 | 必须验证的事情 |
| --- | --- |
| world-starting-town | 默认零 HUD，地图和角色占据完整画面 |
| world-pause-menu | 入口由贴图引导，没有顶部状态标题和返回按钮 |
| party-single-member | 当前宝可梦由贴图、焦点和状态条引导 |
| bag-potion-list | 分类图标轨道、物品袋网格、数量角标和局部提示清楚 |
| pokedex-seen-and-unseen | 完整贴图和剪影使用同一构图 |
| shop-potion-preview | 物品、价格和确认状态靠视觉层级表达 |
| save-confirm-available | 确认提示是临时状态，不变成固定底栏 |

每个场景都必须通过以下检查：

1. 不看标题，玩家能否通过贴图和焦点找到主要入口。
2. 只用键盘能否完成进入、选择、确认和取消。
3. 鼠标不可用时，核心路径是否仍然完整。
4. 关闭动效后，所有重要信息是否仍然可读。
5. 是否出现了不必要的常驻 HUD、文字按钮或信息卡堆叠。

战斗使用独立 fixture 验收。当前 page demo 没有正式 BattleSession，不把战斗状态偷偷塞进通用 PageDemoContext。战斗画面稳定后，再接入真实 session 的只读投影。

## 八、实施顺序

当前批次先完成玩家页面的静态构图、键盘输入、分类筛选和取消路径。已有角色和宝可梦资源先接入 demo，背包物品仍等待可裁切、无水印的独立素材。战斗 HUD、skin、动效和正式运行时接入继续留在后续阶段。

### H0：接受新的逻辑结构（已完成）

确认本文件中的四种画面模式、键位合同和视觉引导规则。此阶段不修改 Rust。

### H1：在 demo 建立静态构图（玩家页面已完成）

先实现世界、导航、队伍、背包和图鉴的固定画面。战斗保持独立 fixture，待后续补齐自己的 HUD 语义。页面允许真实资源和几何占位并存，以便先验证位置、焦点和信息层级。

### H2：接入语义资源槽位（进行中）

把宝可梦、物品、图鉴、训练家卡和战斗命令转换成稳定的资源槽位。当前 demo 已完成世界角色、队伍 Treecko 和图鉴 Treecko 的槽位；页面不直接依赖具体像素素材。背包和训练家卡仍保留占位。

### H3：接入键盘输入合同（玩家页面已完成）

让 demo 能使用默认键位完成所有核心路径，再提供重映射边界。鼠标只接入悬停和确认。

### H4：接入 skin 和动效

静态构图通过验收后，接入像素字体、边框、纹理、选择状态和有限动效。动效可关闭。

### H5：接入正式 game-view

只有 demo 验收记录通过后，才把语义构图、资源槽位和 motion presentation 接入正式项目。demo fixture 不进入正式运行时。

## 九、完成标准

- 世界模式默认零 HUD。
- 导航模式不显示顶部状态标题，不显示返回按钮，入口由贴图和焦点引导。
- 队伍、背包、图鉴和战斗不再共享一套标题加信息卡结构。
- 键盘可以完成所有核心流程；鼠标只是有限辅助。
- 页面语义、skin、资源和动效可以分别修改。
- 战斗只有一套主 HUD 语义。
- 关闭动效后，重要信息仍然可读。
- game-page-demo 可以用固定场景和固定输入路径验收以上规则。
- 正式 game-view 接入前，构图和资源槽位已经被接受。
