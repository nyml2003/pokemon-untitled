# 优化数据记录模板

> 分类：未来；起草：2026-07-26。
> 状态：性能实验记录模板。本文定义比较口径，不表示当前指标已经全部支持。

## 使用规则

每次性能优化至少记录一份优化前基线和一份优化后结果。两份记录必须使用相同的入口、数据、资源、构建配置、窗口尺寸、场景脚本、预热时间、采样时间和指标定义。

只改变一个主要变量。多个优化同时合入时，必须注明收益无法拆分。

结果分为三类：

```text
实测      由程序运行日志直接得到
推导      根据实测值计算得到
估算      尚未实现或尚未运行，只能作为目标范围
```

估算值不能填入“优化后实测”列。

## 标准实验协议

### 环境记录

```text
记录编号：OPT-YYYYMMDD-NNN
优化名称：<一句话描述>
代码版本：<commit 或工作树说明>
数据版本：<内容包、数据集、资源提交或文件摘要>
运行入口：<例如 game-page-demo --demo pokedex>
构建配置：<debug / release / profile 名称>
操作系统：<系统版本>
渲染后端：<Vulkan / DX12 / Metal / 其他>
GPU：<型号>
CPU：<型号>
窗口尺寸：<width>x<height>
显示刷新率：<Hz>
其他限制：<电源模式、后台程序、垂直同步等>
```

默认采样协议：预热 5 秒，单场景采样 30 秒，重复 3 次，报告 3 次结果的中位数，并保留最小值和最大值。首次加载单独记录，不混入稳定帧。

每次运行前关闭上一次进程和旧日志文件。运行后保留原始日志，并记录窗口切换、surface lost、资源缺失或错误恢复。

### 标准场景

| 场景 ID | 场景 | 操作脚本 | 主要观察点 |
| --- | --- | --- | --- |
| `idle` | 静止页面 | 打开目标页面后保持不动 | 是否错误持续重绘 |
| `pokedex-navigate` | 图鉴层级切换 | 列表、详情、种族值、技能之间左右切换 | 模型重建、动画帧率 |
| `pokedex-rapid` | 快速连续切换 | 连续按左右键 10 次，间隔 100~200ms | 动画中断和重定向 |
| `list-scroll` | 列表操作 | 连续按上下键移动 20 项 | 虚拟滚动和选择同步 |
| `pointer` | 有限鼠标操作 | 移动、悬停、点击可交互项 | hover 是否触发无效重绘 |
| `demo-switch` | 页面切换 | 使用 demo 切换键切换 3 次 | 初始化和模型缓存失效 |

只执行实际相关的场景，但报告必须说明跳过了哪些场景。

## 指标定义

### 帧频和时间

| 字段 | 定义 | 单位 |
| --- | --- | --- |
| `wall_fps` | 统计窗口内帧数 / 墙钟时间 | FPS |
| `active_fps` | 帧数 / 所有 redraw 工作时间之和 | FPS |
| `frame_avg` | 所有帧总耗时 / 帧数 | ms |
| `frame_p50` | 帧耗时中位数 | ms |
| `frame_p95` | 帧耗时第 95 百分位 | ms |
| `frame_p99` | 帧耗时第 99 百分位 | ms |
| `frame_max` | 单帧最大耗时 | ms |
| `sample_frames` | 统计窗口内完成的帧数 | count |
| `redraw_requests` | 请求重绘的次数 | count |

`wall_fps` 反映整个观察窗口的更新频率。静止页面时它可能很低，这是正常的。`active_fps` 反映连续执行 redraw 时的能力。动画卡顿时优先看它。

### 阶段耗时

所有阶段单位统一为毫秒：

```text
advance     UI 动画和交互状态推进
model       PageModel 或场景模型投影
tree        UI tree 构建
layout      UI tree 解析和布局
plan        FramePlan / GPU plan 构建
present     GPU 上传、编码和提交
```

`model` 必须继续拆分时使用固定字段：`data_load`、`static_project`、`dynamic_project`。

### 工作量

```text
commands          UI 命令数量
action_hits       action hit 数量
action_targets    interaction target 数量
instances         GPU 实例数量
upload_bytes      本帧上传字节数
pass_count        GPU pass 数量
submit_count      queue submit 次数
text_labels       文本标签数量
redraw_reason     input / animation / pointer / resize / unknown
```

字段暂未被运行时支持时填写 `N/A`，不要用 `0` 伪造数据。

变化计算规则：

```text
耗时变化 = 优化后 - 优化前
耗时改善率 = (优化前 - 优化后) / 优化前 * 100%
FPS 变化 = 优化后 - 优化前
FPS 提升率 = (优化后 - 优化前) / 优化前 * 100%
```

耗时改善率为正表示变快。FPS 提升率为正表示变快。

## 比较规则和通过条件

优化前后必须比较同一个场景的 P95。平均值只用于观察总体趋势，不能单独作为通过条件。

```text
目标阶段 P95 至少下降 20%
总帧 P95 不超过 16.67ms
动画场景 active_fps >= 60
其他场景没有超过 10% 的 P95 回归
没有新增输入错误、旧画面、资源缺失或提交失败
```

如果优化目标是静止帧省电，还要记录 `idle wall_fps`、`idle redraw_requests` 和 `idle active_elapsed`。静止页面不应通过持续重绘提高 `wall_fps`，成功标准是降低重绘次数和活跃耗时。

原始日志必须保留。汇总表不能替代原始日志。
